# ISU-041: 2022-12-tessera#h-04

## Published report facts

- **Root cause:** Update pendingBalances only after new proposal creation.
- **Documented consequence:** The old proposer loses the deposit, and the new proposer can repeat the proposal.
- **Documented fix:** Update pendingBalances before calling _setListing().
- **Report:** https://code4rena.com/reports/2022-12-tessera#h-04-optimisticlistingseaportpropose-sets-pendingbalances-of-newly-added-proposer-instead-of-previous-one
