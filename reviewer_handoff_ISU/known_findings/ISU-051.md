## Published report facts

- **Root cause:** In the constructor, only the 0th Generation (Generation 0) is initialized as 3, while subsequent generations (Generation 1, Generation 2, etc.) are not initialized.
- **Documented consequence:** The mapping is uninitialized, resulting in a rollback of the calculation with a divide-by-zero error.
- **Documented fix:** Logic should be added to the contract to allow administrators to correctly initialize or update the numElements map each time a new generation is created.
- **Report:** https://code4rena.com/reports/2024-02-ai-arena#h-07-fighters-cannot-be-minted-after-the-initial-generation-due-to-uninitialized-numelements-mapping
